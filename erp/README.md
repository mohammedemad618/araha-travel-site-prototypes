# نيورا ERP — نظام إدارة شركات السياحة

لوحة تحكم متعددة الشركات (Multi-tenant) تدير عمل شركة السياحة كاملاً، وترتبط بموقعها الإلكتروني:
الطلبات (CRM) ← العملاء والمسافرون ← الحجوزات والمقاعد ← المدفوعات والموردون ← التأشيرات ← التقارير.

> English summary at the end.

## الأقسام

| القسم                 | ماذا يفعل                                                                                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **لوحة القيادة**      | أرقام اليوم، والتحصيل الشهري، وتنبيهات: مهام متأخرة، جوازات تنتهي، حجوزات قريبة عليها مبالغ، تأشيرات قيد المعالجة                                                                          |
| **عروض الأسعار**      | عرض مسعّر من الطلب أو العميل: خدمات بأسعارها وتكلفتها المتوقعة والربح، وصلاحية، وطباعة. يُعلَّم «مُرسل» أو «مرفوض»، وقبوله يحوّله إلى حجز بكل خدماته بنقرة                                 |
| **الطلبات**           | كل استفسارات الموقع والواتساب والهاتف. لوحة مراحل (جديد ← تم التواصل ← عرض سعر ← تم الحجز / لم يتم)، وسجل متابعة، ومهام، وتحويل بنقرة إلى عميل وحجز                                        |
| **العملاء**           | ملف لكل عميل مع أفراد العائلة والجوازات وتواريخ انتهائها، وحجوزاته وتأشيراته ومرفقاته (صور الجوازات وPDF)                                                                                  |
| **الباقات والمواعيد** | الباقات التشغيلية ومواعيد الانطلاق وعدد المقاعد. المقاعد تُحسب تلقائياً من الحجوزات، ولا يُسمح بتجاوزها                                                                                    |
| **الحجوزات**          | الرحلة خدمات منفصلة (طيران، فندق، تأشيرة، نقل، جولة، تأمين، باقة)، لكل خدمة مورد وتكلفة وحالة (لم تُطلب ← طُلبت ← مؤكدة) ورقم تأكيد وتواريخ. مع الخصم والمسافرين والربح وكشف الحجز المطبوع |
| **الفواتير**          | فاتورة برقم ثابت تصدر من الحجز، وتُلغى برقمها مع ذكر السبب، وتظهر حالة دفعها وتنبيه إن تغيّر الحجز بعدها                                                                                   |
| **المدفوعات**         | دفعات واستردادات بالدينار أو الدولار مع التحويل بسعر الصرف، وإيصال قبض مطبوع، وإلغاء الإيصال مع إعادة حساب الرصيد                                                                          |
| **الموردون**          | الفنادق وشركات الطيران ووكلاء التأشيرات، والتكاليف المسجلة عليهم، والمدفوع لهم، والمستحق                                                                                                   |
| **التأشيرات**         | متابعة طلب كل مسافر من جمع المستندات حتى الإصدار                                                                                                                                           |
| **المحاسبة**          | قيود مزدوجة تلقائية، ودليل حسابات، ومصروفات، وقيود يدوية، وكشف حساب لكل حساب، وقائمة الدخل والميزانية العمومية وميزان المراجعة                                                             |
| **التقارير**          | المبيعات والتحصيل والأرباح شهرياً، وحسب الباقة والمصدر والموظف، والمبالغ المستحقة على العملاء                                                                                              |
| **الإعدادات**         | بيانات الشركة وسعر الصرف واللون، والفروع، والمستخدمون والصلاحيات ونطاق الرؤية، وربط الموقع، وسجل العمليات                                                                                  |
| **إدارة المنصة**      | لنيورا فقط: إضافة الشركات المشتركة وإيقافها والدخول إليها للدعم                                                                                                                            |

الواجهة بالعربية (من اليمين لليسار) وبالإنجليزية، وتعمل على الموبايل.

## الصلاحيات

| الدور  | يستطيع                                                 |
| ------ | ------------------------------------------------------ |
| مالك   | كل شيء، ومنه إدارة المستخدمين                          |
| مدير   | كل شيء عدا إدارة المستخدمين                            |
| مبيعات | الطلبات والعملاء والحجوزات والتأشيرات، ورؤية المدفوعات |
| محاسب  | المالية والموردون والتقارير، ورؤية الحجوزات والعملاء   |
| عمليات | الحجوزات والباقات والمقاعد والتأشيرات والعملاء         |
| مشاهد  | قراءة فقط                                              |

### دورة البيع

طلب ← عرض سعر ← حجز (خدمات الرحلة) ← فاتورة ← دفعات.

- العرض المقبول يصبح حجزاً بنفس الخدمات، وكل خدمة تبدأ بحالة «لم تُطلب».
- يتابع فريق العمليات كل خدمة مع مورّدها حتى «مؤكدة»، مع رقم التأكيد.
- لوحة القيادة تنبّه إلى الرحلات القريبة التي فيها خدمات غير مؤكدة.
- الخدمة الملغاة تبقى في السجل، لكنها لا تُحسب في المبيعات ولا في رصيد المورد.

### المحاسبة

كل حركة مالية تصبح قيداً مزدوجاً متوازناً بعملة الشركة، ولا يُحذف أي قيد.

| الحدث               | القيد                                                             |
| ------------------- | ----------------------------------------------------------------- |
| تأكيد حجز           | مدين ذمم العملاء / دائن إيرادات الرحلات                           |
| تكلفة خدمة لدى مورد | مدين تكلفة الرحلات / دائن ذمم الموردين                            |
| دفعة من عميل        | مدين الصندوق أو البنك أو المحفظة (حسب الطريقة) / دائن ذمم العملاء |
| استرداد لعميل       | عكس الدفعة                                                        |
| دفعة لمورد          | مدين ذمم الموردين / دائن الصندوق أو البنك                         |
| مصروف               | مدين بند المصروف / دائن الحساب الذي دُفع منه                      |

- تعديل الحجز (السعر، التكلفة، المورد، الإلغاء) يُسجَّل بقيد تسوية بالفرق فقط، فلا يُحتسب مرتين.
- إلغاء الإيصال أو المصروف يُسجَّل بقيد عكسي.
- عند فتح المحاسبة أول مرة يُنشأ دليل الحسابات، وتُرحَّل كل السجلات السابقة تلقائياً.
- زر «مزامنة القيود» يعيد الفحص ويرحّل أي شيء ناقص، ويمكن تشغيله في أي وقت دون تكرار.
- الحجز بعملة أخرى يُحوَّل بسعر الصرف وقت التسجيل.
- القيود اليدوية لأرصدة الافتتاح ورأس المال والتحويلات. يجب أن تتوازن، وتُعكس ولا تُحذف.
- الصلاحية: المالك والمدير والمحاسب يرون المحاسبة، والمشاهد يراها قراءة فقط.

### الفروع ونطاق الرؤية

- لكل شركة فرع رئيسي يُنشأ تلقائياً، ويمكن إضافة فروع أخرى من **الإعدادات ← الفروع**.
- كل طلب وحجز ودفعة وتأشيرة يتبع فرعاً:
  - الحجز المحوَّل من طلب يبقى في فرع الطلب.
  - الدفعة تتبع فرع حجزها.
  - طلبات الموقع تصل إلى الفرع الرئيسي.
- العملاء والباقات والموردون مشتركة للشركة كلها. المقاعد تُحسب من حجوزات كل الفروع.
- لكل مستخدم **نطاق رؤية**:
  - **كل الشركة**: يرى كل شيء، ويمكنه تضييق القوائم ولوحة القيادة والتقارير على فرع واحد من أعلى الصفحة.
  - **فروع محددة**: يرى سجلات فروعه فقط.
  - **سجلاته فقط**: يرى ما أُسند إليه أو أنشأه.
- التقارير تعرض المبيعات والتحصيل والأرباح **حسب الفرع**.
- الفرع المغلق تبقى سجلاته، لكن لا تُضاف إليه سجلات جديدة.

### شخص واحد في أكثر من شركة

- إضافة بريد له حساب مسبق في شركة أخرى تمنحه الوصول بكلمة مروره نفسها، ويتنقل بين شركاته من أعلى الصفحة.
- لكل شركة دوره ونطاقه الخاص.
- لا تستطيع شركة إعادة تعيين كلمة مرور حساب يعمل في شركة أخرى.
- إيقافه في شركة لا يؤثر على وصوله إلى غيرها.

تنزيل القوائم الكاملة (CSV) متاح للمالك والمدير والمحاسب فقط. كل صفحة وكل إجراء يُتحقق منه على الخادم، وبيانات كل شركة معزولة عن غيرها.

## النشر (مرة واحدة)

### 1) قاعدة البيانات — MongoDB Atlas

1. أنشئ Cluster (الخطة المجانية M0 تكفي للبداية). اختر **AWS / us-east-2 (Ohio)** ليكون قريباً من دوال Netlify.
2. **Database Access**: أنشئ مستخدماً بكلمة مرور قوية وصلاحية readWrite.
3. **Network Access**: أضف `0.0.0.0/0`، لأن عناوين Netlify متغيرة. الحماية هنا هي كلمة مرور المستخدم القوية.
4. **Connect ← Drivers**: انسخ رابط الاتصال `mongodb+srv://…`.

### 2) موقع Netlify جديد للنظام

1. Netlify ← Add new project ← Import from GitHub ← نفس المستودع.
2. **Base directory**: `erp`. الأوامر تُقرأ تلقائياً من `erp/netlify.toml`.
3. **Environment variables**:
   - `MONGODB_URI` = رابط Atlas.
   - `MONGODB_DB` = `niura_erp` (اختياري).
4. انشر، ثم افتح `‎/api/health` على رابط النظام للتأكد من الاتصال بقاعدة البيانات:
   - `"database": "connected"` يعني أن الاتصال يعمل.
   - `auth_failed`: اسم المستخدم أو كلمة المرور في الرابط خطأ.
   - `unreachable`: أضف `0.0.0.0/0` في Network Access.
   - `bad_uri`: الرابط نفسه غير صحيح.
5. افتح رابط الموقع. أول زيارة تفتح صفحة **إعداد المنصة** لإنشاء حساب مدير نيورا، وهي تعمل مرة واحدة فقط.
6. من **إدارة المنصة** أضف الشركة الأولى. تظهر كلمة مرور مؤقتة لمالكها، يغيّرها عند أول دخول.

### 3) ربط موقع الشركة بالنظام

داخل الشركة، في **الإعدادات ← ربط الموقع**:

1. ضع **رابط الموقع** (مثل `https://araha-travel.netlify.app`) واحفظ.
2. انسخ **رابط النظام** و**مفتاح الموقع العام**.
3. في Netlify لموقع الشركة، أضف متغيرين:
   - `ERP_URL` = رابط النظام.
   - `NEXT_PUBLIC_ERP_KEY` = المفتاح العام (يبدأ بـ `pk_`).
4. أعد نشر الموقع. بعدها:
   - كل نموذج في الموقع يصل إلى **الطلبات** فوراً، وتبقى نسخة في Netlify Forms كاحتياط.
   - أسعار ومواعيد ومقاعد الباقات التي يديرها النظام تظهر في الموقع **مباشرة** خلال دقيقة تقريباً، دون إعادة نشر. المواعيد المكتملة تظهر «مكتمل»، والمحدودة تعرض عدد المقاعد المتبقية.
   - إن تعذّر الوصول إلى النظام يعرض الموقع آخر نسخة مبنية.
5. اختياري: أنشئ Build hook في Netlify لموقع الشركة، وضعه في خانة **Build hook**. زر **تحديث الموقع** في صفحة الباقات يعيد بناء الموقع، وهذا مفيد لمحركات البحث وللنسخة الاحتياطية. الأسعار والمقاعد لا تحتاجه.
6. لتسريع البداية، استخدم زر **استيراد من الموقع** في صفحة الباقات. يضيف كل باقات الموقع ومواعيدها بنقرة.

### 4) محتوى الموقع من النظام

قسم **محتوى الموقع** يدير كل ما يقرؤه الزائر (لم تعد هناك لوحة `/admin` في الموقع):

- **برامج الرحلات:** صفحة لكل باقة من «الباقات والمواعيد». تشمل النصوص والمزايا والمعلومات السريعة وبرنامج الأيام ويشمل/لا يشمل والصور ومحركات البحث. السعر والمدة والمواعيد تبقى في «الباقات والمواعيد».
- **التأشيرات** و**الوجهات** و**أدلة السفر** (إضافة وتعديل، والأدلة تُحذف أيضاً).
- **الصفحات:** من نحن، والخصوصية، والشروط.
- **الإعدادات والرئيسية:** معلومات الشركة (الهاتف وواتساب والعنوان والدوام وأرقام الثقة وطرق الدفع)، والصفحة الرئيسية بكل أقسامها، وآراء العملاء (يظهر الموثّق فقط)، والأسئلة الشائعة.
- **مكتبة الصور:** رفع JPG/PNG/WebP حتى 5 ميغابايت. الصور عامة، ولا تُحذف صورة مستخدمة.
- **معاينة حية:** بجانب كل محرر (أو بزر «معاينة» على الشاشات الصغيرة) صورة تقريبية للصفحة بألوان الموقع، تتحدث مع كل حرف، بالعربية أو الإنجليزية وبعرض شاشة كبيرة أو جوال، دون حفظ.

طريقة العمل:

1. أنشئ Build hook لموقع الشركة في Netlify (**Site configuration ← Build & deploy ← Build hooks**) وضعه في **الإعدادات ← ربط الموقع**.
2. في **محتوى الموقع** اضغط **استيراد محتوى الموقع الحالي**، فتُنسخ صفحات الموقع كما هي. الضغط مرة أخرى يضيف الأقسام الجديدة فقط ولا يمس ما عدّلته.
3. كل **حفظ ونشر** يعيد بناء الموقع تلقائياً، بحد أقصى مرة كل 90 ثانية. التعديلات بين بناءين تنتظر الحفظ التالي أو زر **انشر الآن**.

عند البناء يسحب الموقع المحتوى من `‎/api/public/v1/content` (بالمفتاح العام)، وينزّل صور المكتبة إلى `public/uploads/erp`، ويكتبها فوق ملفات `content/`. يتحقق النظام من كل صفحة بنفس قواعد الموقع قبل الحفظ. إن فشل البناء لأي سبب تبقى النسخة السابقة منشورة.

## التطوير والاختبار محلياً

```bash
cd erp
npm install
node scripts/local-mongo.mjs 27077 ./.data   # قاعدة MongoDB محلية بدون Atlas
echo "MONGODB_URI=mongodb://127.0.0.1:27077/" > .env.local
npm run dev                                   # http://localhost:3100

npm run lint && npm run typecheck
npm run build && npm run test:e2e             # اختبارات كاملة على قاعدة مؤقتة
```

## البنية

- **Next.js 15** (App Router, Server Components, Server Actions) و**React 19** و**Tailwind 4**.
- **MongoDB** عبر المشغّل الرسمي. الفهارس تُنشأ تلقائياً عند أول اتصال (`lib/indexes.ts`).
- **العزل بين الشركات** عبر طبقة وصول موحّدة (`lib/repo.ts`):
  - كل استعلام يمر بها، فتضيف `tenantId` تلقائياً، وتختم به كل إضافة.
  - للطلبات والحجوزات والدفعات والتأشيرات، تضيف أيضاً نطاق رؤية المستخدم (الفرع أو سجلاته). القواعد في `lib/scope.ts` ومغطاة باختبارات.
  - `repo(ctx).all` يتجاوز نطاق الفرع فقط، لا الشركة. يُستخدم للمجاميع وفحوص السلامة، مثل المقاعد وأرصدة الموردين ومنع حذف عميل له حجوزات في فرع آخر.
  - صفحة سجل خارج نطاق المستخدم تظهر «غير موجودة».
- **العضويات**: المستخدم حساب دخول فقط، ودوره ونطاقه وفروعه محفوظة في `memberships` لكل شركة.
- **ترحيل البيانات**: يعمل تلقائياً عند أول اتصال (`lib/migrations.ts`)، ويمكن تشغيله أكثر من مرة دون ضرر. حوّل المستخدمين القدامى إلى عضويات، وأنشأ الفرع الرئيسي، وربط السجلات القديمة به.
- **تسجيل الدخول**:
  - كلمات المرور مشفّرة بـ scrypt.
  - الجلسات في قاعدة البيانات بكوكي httpOnly، وتنتهي بعد 14 يوماً.
  - حد لمحاولات الدخول.
  - كلمة مرور مؤقتة تُغيَّر إلزامياً عند أول دخول.
  - تغيير كلمة المرور يُخرج بقية الأجهزة.
- **المال**:
  - المبالغ أعداد صحيحة: دنانير كاملة، والدولار بالسنت.
  - كل دفعة وتكلفة تُحوَّل إلى عملة الحجز بسعر الصرف وقت تسجيلها.
- **المرفقات**: تُخزَّن في GridFS حتى 5 ميغابايت (JPG/PNG/WebP/PDF). نوع الملف يُفحص من محتواه لا من امتداده.
- **الواجهة البرمجية العامة** (`/api/public/v1`):
  - `leads` يستقبل الطلبات بمفتاح عام لا يسمح إلا بإضافة طلبات، مع فحص النطاق وحد للطلبات وحماية من البوتات.
  - `catalog` يعرض الأسعار والمقاعد فقط، بلا أي بيانات عملاء.
- **سجل العمليات** لكل إجراء مهم: الدخول، والحذف، والدفعات، والتصدير، والصلاحيات.

## استعادة حساب مدير المنصة

إذا ضاع بريد مدير المنصة أو كلمة مروره:

1. أضف في إعدادات موقع النظام على Netlify المتغير `ADMIN_RESET_TOKEN`، بقيمة عشوائية من 32 حرفاً على الأقل، ثم أعد النشر.
2. افتح `‎/reset-admin`، وأدخل الرمز مع البريد وكلمة المرور الجديدين. تُغلق كل جلسات الحساب القديمة.
3. احذف المتغير وأعد النشر. الصفحة لا تظهر أصلاً دون المتغير.

## النسخ الاحتياطي

Atlas يأخذ نسخاً احتياطية تلقائية في الخطط المدفوعة. على الخطة المجانية صدّر البيانات دورياً عبر `mongodump`، أو من أزرار **تصدير CSV** في النظام.

## English summary

Multi-tenant back office for travel agencies, linked to their websites:

- CRM: lead pipeline, customers and their travellers with passports.
- Accounting: an automatic double-entry ledger in the company currency.
  - Bookings post revenue and supplier costs as differences; payments, supplier payments and expenses each post once.
  - Voids post reversals; nothing is deleted.
  - Also includes a chart of accounts, manual entries, account statements, income statement, balance sheet and trial balance.
- Sales cycle: lead → quote → booking → invoice → payments.
  - Quotes: priced service lines, validity, printing; accepting one creates the booking.
  - Bookings are trips made of services (flight, hotel, visa, transfer, tour…). Each has its supplier, cost, status and confirmation number.
  - Invoices are numbered, voidable copies of a booking's sale lines.
- Branches and memberships:
  - Leads, bookings, payments and visas belong to a branch.
  - Staff see the whole company, selected branches, or only their own records.
  - One login can belong to several companies, with a company switcher.
  - Every query goes through a tenant-aware repository (`lib/repo.ts`) that adds the company and the member's scope automatically.
- Operations: packages with departure dates and seat control, bookings with sale items, supplier costs and profit, visa tracking.
- Finance: IQD/USD payments and refunds, printable invoices and receipts, supplier balances.
- Reports, roles and permissions, an audit log, CSV export, and Arabic/English (RTL/LTR).
- Website content: every website section (trip programs, visas, destinations, guides, pages, company details, home page, testimonials, FAQ) and an image library edited in the back office, replacing the old /admin CMS; each save rebuilds the website through its build hook (at most every 90 s), and the build pulls `/api/public/v1/content` and downloads library images.
- Lost platform-admin access: set `ADMIN_RESET_TOKEN` (32+ chars), redeploy, use `/reset-admin`, then remove it.

**Deploy:**

1. Create a MongoDB Atlas cluster.
2. Create a Netlify site from this repository with base directory `erp`, and set `MONGODB_URI`.
3. Open the site; the first visit runs the one-time platform setup.
4. Add companies from **Platform admin**.

**Connect a website:**

1. In the company's **Settings → Website connection**, set the site URL.
2. On the website's Netlify site, add `ERP_URL` and `NEXT_PUBLIC_ERP_KEY`.
3. Redeploy the website.
   - Its forms then create leads in the ERP.
   - Its pages show the ERP's current prices, dates and seats left, live (read in the browser through the site's `/erp-api` proxy).
   - Builds keep a fallback copy.

**Tests:** `npm run build && npm run test:e2e` runs end-to-end flows against a throwaway MongoDB. The flows cover setup, companies, the public API, conversion, seat limits, multi-currency payments, tenant isolation, roles and language.
